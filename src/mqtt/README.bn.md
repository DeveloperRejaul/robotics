# MQTT দিয়ে স্মার্ট ডিভাইস: প্রতিটি ইউজার নিজের ESP32 যুক্ত করে

[English](README.md) | **বাংলা**

প্রতিটি ESP32 তে **একই প্রোগ্রাম** থাকে। প্রতিটি ইউজার ফোন থেকে ডিভাইসকে **নিজের Wi-Fi** তে যুক্ত করে, তারপর **ওয়েব পেজে** ডিভাইসের ডেটা দেখে ও ডিভাইস চালায়। কাউকে কোড বদলাতে হয় না। ডিভাইস সার্ভারের সাথে **MQTT ব্রোকারের** মাধ্যমে কথা বলে।

```
                                  ┌──────────── আপনার কম্পিউটার / সার্ভার ──────────┐
 ESP32 (esp32.py)  ──Wi-Fi──▶     │  mqtt.py   MQTT ব্রোকার        :1883            │
   সব ডিভাইসে একই                  │     ▲  ▼                                       │
   ফাইল                           │  server.py  ওয়েব পেজ + API    :8080            │
                                  │             + মেমরি (লিস্ট)                    │
 ফোন / ব্রাউজার  ◀────────────────│                                                │
                                  └────────────────────────────────────────────────┘
```

| ফাইল | কাজ |
|------|-----|
| [mqtt.py](mqtt.py) | **MQTT ব্রোকার।** ডিভাইস নিজের গোপন চাবি দিয়ে লগইন করে এবং শুধু নিজের টপিক ব্যবহার করতে পারে। |
| [server.py](server.py) | **ওয়েব পেজ + API সার্ভার।** পেজ ([index.html](index.html)) দেয়, ইউজার, ডিভাইস দাবি, রিডিং জমা, কমান্ড পাঠানো। ব্রোকার থেকে ডেটা শোনে। |
| [esp32.py](esp32.py) | **ডিভাইসের প্রোগ্রাম** (MicroPython)। সেটআপ হটস্পট, Wi-Fi সেভ, MQTT। |
| [setup_device.py](setup_device.py) | কম্পিউটার থেকে (USB দিয়ে) একটি ডিভাইস তৈরি বা আপডেট করে। |
| [store.py](store.py) | শেয়ার করা নিরাপত্তার কোড ও ডিভাইসের তালিকা `devices.json` (ডিভাইসের ID ও চাবির hash)। **কোনো ডেটাবেস নেই।** |
| [config.py](config.py) | পোর্ট ও ঠিকানা। |

## ইউজার কীভাবে ডিভাইস সেটআপ করে

1. ডিভাইসে **পাওয়ার দিন**। এতে এখনো Wi-Fi নেই, তাই এটা নিজের হটস্পট `SmartDevice-XXXX` খোলে (LED ধীরে জ্বলে-নেভে)।
2. ফোনে ওই হটস্পটে জয়েন করুন। **পাসওয়ার্ড হলো বক্সে ছাপা ক্লেইম কোড।**
3. সেটআপ পেজ নিজে খুলবে (না খুললে `http://192.168.4.1`)।
4. নিজের Wi-Fi (2.4 GHz) বেছে পাসওয়ার্ড লিখুন, **Save** চাপুন। ডিভাইস রিস্টার্ট হয়ে আপনার Wi-Fi তে ঢোকে।
5. ফোনকে আবার স্বাভাবিক Wi-Fi তে যুক্ত করে ওয়েব পেজ খুলুন।
6. **অ্যাকাউন্ট খুলুন** (বা লগইন করুন), **Add device** চাপুন, বক্সের **Device ID** ও **Claim code** দিন।
7. ডিভাইসটি লাইভ ডেটাসহ দেখা যাবে। LED চালু-বন্ধ, ইতিহাস কত ঘন ঘন জমবে তা বদলানো এবং ইতিহাস দেখা যায়।

ডিভাইস অন্য Wi-Fi তে নিতে **BOOT বাটন ৫ সেকেন্ড চেপে ধরুন**। এতে Wi-Fi ভুলে সে ধাপ ১ এ ফিরে আসে।

## ডেটা কোথায় থাকে

কোনো **ডেটাবেস নেই**। ইউজার, লগইন, ডিভাইসের মালিক, live মান ও history সব `server.py` এর ভেতরের সাধারণ Python লিস্টে (`USERS`, `TOKENS`, `DEVICES`, `READINGS`) থাকে। **`server.py` বন্ধ হলে সব মুছে যায়**: রিস্টার্টের পর ইউজারকে আবার রেজিস্টার করতে, ডিভাইস আবার claim করতে হয় এবং history ফাঁকা থেকে শুরু হয় (চলার সময় শেষ ২০০০০টি রিডিং রাখা হয়)। শুধু `devices.json` থেকে যায়: এতে প্রতিটি ডিভাইসের ID এবং তার চাবি ও claim code এর *hash* থাকে, তাই রিস্টার্টের পরেও ব্রোকার আপনার ডিভাইস চিনতে পারে।

## দ্রুত শুরু

```bash
source .venv/bin/activate
pipenv install                     # একবার
```

প্রজেক্টের রুট ফোল্ডার থেকে দুটি প্রোগ্রাম চালু করুন, প্রতিটি আলাদা টার্মিনালে:

```bash
python src/mqtt/mqtt.py --lan      # ১. ব্রোকার (--lan দিলে আপনার Wi-Fi এর ডিভাইস কানেক্ট করতে পারে)
python src/mqtt/server.py          # ২. ওয়েব পেজ + API (পোর্ট 8080)
```

প্রতিটি নিজের ঠিকানা ছাপে। ফোনে `server.py` এর ছাপা ঠিকানা খুলুন, যেমন `http://192.168.50.64:8080`। এই পরীক্ষায় ফোন, কম্পিউটার ও ডিভাইস একই Wi-Fi তে থাকতে হবে।

**ডিভাইস তৈরি করুন** (বোর্ড USB তে, আগে থেকে MicroPython থাকতে হবে)। `--host` হলো এই কম্পিউটারের ঠিকানা, **ডিভাইস যেভাবে দেখে**:

```bash
python src/mqtt/setup_device.py --host 192.168.50.64
```

এটা বক্সের লেবেল ছাপে:

```
 Device ID  : esp32-a1b2c3d4e5f6
 Claim code : ABCD-2345
 Setup Wi-Fi: SmartDevice-E5F6 (password = claim code)
```

লেবেল `labels.csv` ফাইলেও সেভ হয় (ব্যক্তিগত, গিটে যায় না)। এরপর ওপরের ইউজারের ধাপগুলো করুন।

**ইতিমধ্যে সেটআপ করা ডিভাইস আপডেট করুন** (নতুন প্রোগ্রাম, বা কম্পিউটারের ঠিকানা বদলেছে)। এতে ডিভাইসের ID, চাবি, মালিক ও সেভ করা Wi-Fi থেকে যায়:

```bash
python src/mqtt/setup_device.py --update --host 192.168.50.64
```

একেবারে নতুন করে তৈরি করতে (নতুন চাবি ও ক্লেইম কোড, Wi-Fi মুছে): `setup_device.py --force --host ...`।

## MQTT টপিক

প্রতিটি ডিভাইসের নিজের টপিক, `devices/<ডিভাইস id>/...`

| টপিক | দিক | বিষয়বস্তু |
|------|-----|-----------|
| `devices/<id>/data` | ডিভাইস → সার্ভার | `{"temperature":27.5,"humidity":60,"sensor_value":512,"uptime":120,"led":false}` প্রতি ৫ সেকেন্ডে |
| `devices/<id>/status` | ডিভাইস → সার্ভার (retained) | `online` / `offline`। পাওয়ার বা Wi-Fi গেলে ব্রোকার ডিভাইসের হয়ে `offline` পাঠায় (MQTT "last will")। |
| `devices/<id>/cmd` | সার্ভার → ডিভাইস | `{"led":true}` |

## ব্রোকারে কে কী করতে পারে

| কে | লগইন | অনুমতি |
|----|------|--------|
| ডিভাইস | নিজের ID + চাবি | নিজের `data` ও `status` এ লেখা, নিজের `cmd` শোনা। **আর কিছু না।** |
| `server.py` | ইউজার `server` + `.server_secret` ফাইলের চাবি (নিজে তৈরি হয়, ব্যক্তিগত) | সবকিছু |
| অন্য কেউ | – | প্রত্যাখ্যাত |

ইউজার কখনো ব্রোকারে যায় না। সে ওয়েব পেজ ব্যবহার করে, যা API ব্যবহার করে। ইউজার শুধু নিজের দাবি করা ডিভাইস দেখে ও চালায়।

## ওয়েব API (ওয়েব পেজ ব্যবহার করে)

ইন্টারঅ্যাক্টিভ ডকুমেন্ট: `http://SERVER:8080/docs`

| অনুরোধ | কাজ |
|--------|-----|
| `POST /api/register`, `/api/login`, `/api/logout` | অ্যাকাউন্ট। লগইনে টোকেন আসে (`Authorization: Bearer ...`)। |
| `GET /api/devices` | ইউজারের নিজের ডিভাইস ও লাইভ ডেটা। |
| `POST /api/devices/claim` | ডিভাইস যোগ: `{"device_id", "claim_code", "name"}`। |
| `GET /api/devices/{id}/history?limit=50` | জমা রিডিং, নতুন আগে। |
| `POST /api/devices/{id}/cmd` | `{"led": true}` এবং/অথবা `{"interval": 30}` (ইতিহাস কত ঘন ঘন জমবে, ৫ থেকে ৩৬০০ সেকেন্ড)। |
| `DELETE /api/devices/{id}` | অ্যাকাউন্ট থেকে ডিভাইস সরানো (ইতিহাস মুছে যায়)। |
| `GET /api/health` | সার্ভার চলছে কি না এবং ব্রোকারের সাথে যুক্ত কি না। |

## এই পরীক্ষামূলক সংস্করণে নিরাপত্তা

- পাসওয়ার্ড salt সহ hash করে রাখা হয়। ডিভাইসের চাবি ও ক্লেইম কোড শুধু hash আকারে থাকে।
- প্রতিটি ডিভাইসের নিজের চাবি আছে এবং সে শুধু নিজের টপিক ব্যবহার করতে পারে।
- লগইন, রেজিস্টার ও ক্লেইমের চেষ্টা সীমিত। অন্যের ডিভাইস চাইলে "not found" আসে।
- সেটআপ না হওয়া ডিভাইসের হটস্পট ক্লেইম কোড দিয়ে সুরক্ষিত।
- বোর্ডে কপি করার পর `setup_device.py` ডিভাইসের চাবি আপনার কম্পিউটারে রাখে না।

**ইনবিল্ট ব্রোকারের জানা সীমাবদ্ধতা।** `amqtt` ব্রোকার একই client id নিয়ে *যে কেউ* ঢুকতে চাইলে পাসওয়ার্ড যাচাইয়ের **আগেই** ওই client এর সেশন মুছে দেয়। আক্রমণকারী প্রত্যাখ্যাত হয়, কিন্তু আসল client কানেক্টেড থেকেও মেসেজ পাওয়া বন্ধ করে দেয়। ডিভাইস ID বক্সে ছাপা থাকে, তাই আপনার নেটওয়ার্কের কেউ এটা করতে পারে। ক্ষতি কমাতে `server.py` নিজেকে পিং করে এবং পিং ফিরে না এলে (প্রায় ৩০ সেকেন্ডে) আবার কানেক্ট করে, আর প্রতিটি ডিভাইস ৫ মিনিট পরপর আবার কানেক্ট করে। আসল কাস্টমারের জন্য **Mosquitto** ব্যবহার করুন, যা আগে পাসওয়ার্ড যাচাই করে।

## এখনো নেই (আসল কাস্টমারের আগে লাগবে)

| যা নেই | কেন গুরুত্বপূর্ণ |
|--------|-----------------|
| **TLS / HTTPS** | পাসওয়ার্ড, টোকেন, চাবি ও ডেটা এনক্রিপ্ট ছাড়া যায়। বাসায় পরীক্ষার জন্য ঠিক, ইন্টারনেটে **নিরাপদ নয়**। ব্রোকার ও API TLS এর পেছনে রাখুন এবং `mqtts` / `https` ব্যবহার করুন। |
| **ক্লাউড সার্ভার** | এই পরীক্ষা আপনার কম্পিউটারে চলে। অন্য জায়গার ইউজারদের জন্য পাবলিক ঠিকানার সার্ভার লাগবে। |
| **প্রোডাকশনে Mosquitto** | ওপরের সীমাবদ্ধতা দেখুন। প্রজেক্টের বাকি অংশ ওতেও একইভাবে চলে (ডিভাইসের পাসওয়ার্ড যাচাই ও টপিকের নিয়ম সেখানে বসাতে হবে)। |
| **অফলাইনে ডেটা জমানো** | Wi-Fi বা ইন্টারনেট গেলে সেই সময়ের রিডিং হারায়। |
| **দূর থেকে ফার্মওয়্যার আপডেট (OTA)** | ১০০ ডিভাইসে ভুল ঠিক করতে আজ ক্যাবল লাগে। |
| **পাসওয়ার্ড রিসেট, ইমেইল** | ইউজার শুধু ইউজারনেম দিয়ে লগইন করে। |
| **আসল সেন্সর** | `esp32.py` এর `read_sensor()` এখন র‍্যান্ডম সংখ্যা দেয়। বদলে নিন। |
| **প্রোডাকশন ফ্ল্যাশ স্ক্রিপ্ট** | `setup_device.py` একটা একটা করে করে এবং বোর্ডে আগে থেকে MicroPython থাকতে হয়। |

| ফোন বলছে হটস্পটে ইন্টারনেট নেই | স্বাভাবিক। কানেক্টেড থাকুন, সেটআপ পেজে ইন্টারনেট লাগে না। |
| সেটআপ পেজ নিজে খোলে না | `http://192.168.4.1` খুলুন। |
| সেভের পর হটস্পট আবার ফিরে আসে | Wi-Fi এর নাম বা পাসওয়ার্ড ভুল, অথবা নেটওয়ার্ক শুধু 5 GHz। ২০ সেকেন্ড পর ডিভাইস সেটআপে ফিরে আসে। আবার চেষ্টা করুন। |
| ওয়েব পেজে ডিভাইস "Offline" থাকে | ডিভাইসকে ব্রোকারে পৌঁছাতে হবে: একই Wi-Fi, `mqtt.py --lan` চালু, আর `--host` এ কম্পিউটারের বর্তমান IP। IP বদলালে `setup_device.py --update --host নতুন_IP` চালান। |
| ESP32 `Broker refused this device` ছাপে | ডিভাইস `devices.json` এ নেই (যেমন ফাইলটা মুছে গেছে)। `setup_device.py --force` চালান। |
| ESP32 `Cannot reach the broker` ছাপে | ব্রোকার চলছে না, ফায়ারওয়াল, অথবা ঠিকানা ভুল। |
| ওয়েব পেজে লগইন হয় না / "Cannot reach the server" | `server.py` চালু থাকতে হবে। পেজ ও API একই সার্ভার একই ঠিকানা থেকে দেয়। |
| "Wrong device ID or claim code" | লেবেল থেকে হুবহু কপি করুন। কোডে বড়-ছোট হাতের অক্ষর কোনো ব্যাপার নয়। |
| "This device already belongs to another account" | আগের মালিককে আগে ডিভাইস সরাতে হবে (বা `setup_device.py --force`)। |
| "Too many attempts" | এক মিনিট অপেক্ষা করুন। |
| `server.py` বলছে MQTT ব্রোকারে পৌঁছাতে পারছে না | আগে `mqtt.py` চালু করুন। |

## কী পরীক্ষা করা হয়েছে

কম্পিউটারে, ESP32 হার্ডওয়্যার নকল করে: ব্রোকার ও সার্ভারের ৪০টি পরীক্ষা (কে কানেক্ট করতে পারে, টপিকের অনুমতি, অ্যাকাউন্ট, ডিভাইস দাবি, মালিকানা আলাদা, কমান্ড শুধু সঠিক ডিভাইসে পৌঁছানো, ব্রোকারের last will, ইতিহাস, rate limit, CORS, ওয়েব পেজ), এবং ডিভাইসের রান মোড, সেটআপ পেজ, DNS, BOOT বাটন, ভুল চাবি, ব্রোকার বন্ধ, সেশন মুছে ফেলা ও পাওয়ার কাটা।

আসল ESP32 তে: `setup_device.py --update` দিয়ে প্রোগ্রাম বসানো হয়েছে এবং ডিভাইস **MQTT দিয়ে অনলাইন** হয়েছে, তার ডেটা ডেটাবেসে পৌঁছেছে।

**এখনো পরীক্ষা হয়নি:** আসল ডিভাইসে ওয়েব পেজ থেকে LED চালানো এবং ফোনের ব্রাউজারে ওয়েব পেজ। এগুলো আগে পরীক্ষা করুন।
